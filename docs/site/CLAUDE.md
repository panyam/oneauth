# docs/site — docsite gotchas

- **Diagrams are validated, not eyeballed.** The site renders ```mermaid fences with a pinned mermaid module; a syntax error becomes an error box on the live site. Parse every block with the real parser (`mermaid.parse` under jsdom) before pushing. A bare `"` in a sequence message and `;` in a note each truncate a statement.
- **Publishing a doc needs a content shim plus a nav entry.** `content/<section>/<slug>.html` carries front matter and one `renderMarkdownFile` call; `content/HeaderNavLinks.json` carries the link. The pages under `specs/` were generated by a hand-run script, so a new `docs/oauth/` file isn't published until someone regenerates them.
- **Relative links are rewritten at render time.** `linkRewriter` in `main.go` points a markdown link at the page that renders its target (from the `renderMarkdownFile` calls under `content/`), or at the file on GitHub. A link to a missing file stays relative, and `TestRenderedPagesHaveNoRelativeMarkdownLinks` fails on it (issue 557).
