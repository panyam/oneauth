# stores — backend gotchas

- **Documented-contract bar.** Every exported store method documents error-sentinel mapping, idempotency, transactional scope and non-obvious dances. Match `stores/gae/appstore.go` and `keystore.go`, not sparser neighbours.
- **Run the Datastore emulator with `--consistency=1.0`.** At the default 0.9 a query misses a recent write about one time in ten (issue 395). `docker-compose.yml` passes it, and `make upds` / `make testds` start the emulator and wait for it; CI's `gae` job runs `make testds`. `make downds` first if `testds` turns flaky.
- **`make testpg` shares one Postgres with a 100-client limit.** `setupPostgresDB` must close every connection it opens, or a test with a pooled race (the `usertokentest` one opens 16) pushes the package over it.
- **GAE transactions that race on one entity by design need `datastore.MaxAttempts`.** The default 3 attempts let the fourth concurrent writer fail with `ErrConcurrentTransaction`; `RecordAccessToken` lost access tokens that way about 1 run in 70 (`contendedTxAttempts` in `gae/stores.go`, PR #471).
- **A concurrent GORM test on sqlite needs one connection.** Each pooled `:memory:` connection opens its own empty database. Set `SetMaxOpenConns(1)` for sqlite only (see `gorm/refreshtoken_access_tokens_test.go`) and let `make testpg` exercise a real pool.
- **Single-use values are hashed at rest.** Authorization codes, pushed `request_uri`s and device codes are keyed by `core.AtRestKey`, and the stored record leaves the plaintext out, so a lookup by user code returns `DeviceCode` empty. A new store for a bearer-like value does the same (issues 382, 473). User codes stay plaintext: they're short, and approving one needs a signed-in user.
- **A race test must make its calls overlap.** Start the goroutines behind a barrier, and have each one make a read first so a pooled backend has a live connection per goroutine. Without the warm-up, Postgres connection setup staggers the calls, and the device store's approve race passed 300 runs on Postgres while broken (issue 473). See `deviceauthtest/at_rest.go`.
- **Every FS store refuses a key whose file holds another key's record** (`fs.ErrKeyCollision`). File names are lossy: `safeName` folds `/`, `\` and `:`, Windows folds more, and Windows and macOS ignore letter case. A store keyed by a caller's string reads with `readKeyed` and checks `checkOwner` before a write or delete (issue 505). New FS stores name files by a hash of the key (`fsusertoken_store.go`).
- **Custom store contracts.** `AuthorizationCodeStore` needs atomic `ConsumeAuthorizationCode` + `RecordAuthorizationCodeTokens` (issue 429). `RefreshTokenStore` needs `RecordAccessToken` + `RevokeTokenFamily` atomic per record (issue 436, `refreshtokentest.RunAll`). `outbound.UserTokenStore` needs compare-and-swap on `Version` (`usertokentest.RunAll`). The GORM store does it in one statement and the GAE store in a transaction (issue #468). The optional `core.APIKeyAdmin` (list every key, sweep expired ones) runs `apikeytest.RunAdmin` (issue 549), and the optional `accounts.ChannelAdmin` (list channels by provider, delete one) runs `channeltest.RunAdmin`.
- **GAE users, identities and channels take opt-in options.** `WithSchemaRegistry` upgrades old entities on read through goapplib's `dsmigrate` and stamps `schema_version` on writes (#577). `WithNumericUserKeys` finds users at numeric `IDKey`s for all-digit IDs (#578). Without them the stores read and write as before; `docs/STORES.md` has the usage.
- **GAE queries filter on one property.** The repo ships no `index.yaml`, so a query with an equality on one property plus an inequality on another fails on real Datastore while the emulator accepts it. Filter on the indexed property alone and check the rest in memory, as `CleanupExpiredAPIKeys` does with `HasExpiry` (issue 549).
