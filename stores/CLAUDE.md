# stores — backend gotchas

- **Documented-contract bar.** Every exported store method documents error-sentinel mapping, idempotency, transactional scope and non-obvious dances. Match `stores/gae/appstore.go` and `keystore.go`, not sparser neighbours.
- **Run the Datastore emulator with `--consistency=1.0`.** At the default 0.9 a query misses a recent write about one time in ten (issue 395). `make upds` / `make testds` pass it and wait for the emulator; CI's `gae` job runs `make testds`. `make downds` first if `testds` turns flaky.
- **`make testpg` shares one Postgres with a 100-client limit.** `setupPostgresDB` must close every connection it opens, or a test with a pooled race (the `usertokentest` one opens 16) pushes the package over it.
- **GAE transactions that race on one entity by design need `datastore.MaxAttempts`.** The default 3 attempts let the fourth concurrent writer fail with `ErrConcurrentTransaction`; `RecordAccessToken` lost access tokens that way about 1 run in 70 (`contendedTxAttempts` in `gae/stores.go`, PR #471).
- **A concurrent GORM test on sqlite needs one connection.** Each pooled `:memory:` connection opens its own empty database. Set `SetMaxOpenConns(1)` for sqlite only (see `gorm/refreshtoken_access_tokens_test.go`) and let `make testpg` exercise a real pool.
- **Single-use values are hashed at rest.** Authorization codes, pushed `request_uri`s and device codes are keyed by `core.AtRestKey`, and the stored record leaves the plaintext out, so a lookup by user code returns `DeviceCode` empty. A new store for a bearer-like value does the same (issues 382, 473). User codes stay plaintext: they're short, and approving one needs a signed-in user.
- **A race test must make its calls overlap.** Start the goroutines behind a barrier, and have each one make a read first so a pooled backend has a live connection per goroutine. Without the warm-up, Postgres connection setup staggers the calls, and the device store's approve race passed 300 runs on Postgres while broken (issue 473). See `deviceauthtest/at_rest.go`.
- **FS identity and channel stores refuse a key whose file holds another key's record** (`fs.ErrKeyCollision`), since file names are lossy. New FS stores name files by a hash of the key (`fsusertoken_store.go`).
- **Custom store contracts.** `AuthorizationCodeStore` needs atomic `ConsumeAuthorizationCode` + `RecordAuthorizationCodeTokens` (issue 429). `RefreshTokenStore` needs `RecordAccessToken` + `RevokeTokenFamily` atomic per record (issue 436, `refreshtokentest.RunAll`). `outbound.UserTokenStore` needs compare-and-swap on `Version` (`usertokentest.RunAll`). The GORM store does it in one statement and the GAE store in a transaction (issue #468).
