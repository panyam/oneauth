## Suggested reading order

Roots first; folders that depend on others appear after their dependencies. Each folder name links to that folder's DESIGN.md.

1. [`core/`](core/DESIGN.md) — Foundation types, store interfaces, token/scope primitives, and pluggable security helpers shared by every OneAuth package.
2. [`grpc/`](grpc/DESIGN.md) — Authentication context utilities and server interceptors that propagate the authenticated user ID across the HTTP-to-gRPC boundary via metadata, with optional auth enforcement and switch-user impersonation.
3. [`oauth2/`](oauth2/DESIGN.md) — Self-contained OAuth2 social-login providers (Google, GitHub) with a shared base, PKCE (RFC 7636), and state-cookie CSRF protection that deliver the authenticated user to a host-supplied callback.
4. [`saml/`](saml/DESIGN.md) — Registers SAML 2.0 SSO HTTP routes (login, ACS, logout) on a gorilla/mux router, wrapping crewjam/saml to fit oneauth's redirect-based multi-provider login flow.
5. [`utils/`](utils/DESIGN.md) — Stateless crypto and encoding helpers — RSA/ECDSA key generation, PEM/PKCS8 codec, JWK/JWKS conversion, RFC 7638 kid thumbprints, JWT signing-method lookup, and Flask session-cookie decoding.
6. [`httpauth/`](httpauth/DESIGN.md) — Session-based HTTP auth glue plus standalone middleware for CSRF, security headers, and request body limits.
7. [`localauth/`](localauth/DESIGN.md) — HTTP handlers and store-backed callbacks for local username/password authentication — signup, login, email verification, password reset, and credential linking onto OAuth users.
8. [`client/`](client/DESIGN.md) — Client-side OAuth SDK — discovers authorization servers, drives browser/CLI/M2M login flows, caches and refreshes tokens, and injects them into HTTP requests.
9. [`keys/`](keys/DESIGN.md) — Signing-key storage, kid-indexed lookup, encryption-at-rest, grace-period rotation, and JWKS publication/consumption for OneAuth.
10. [`client/stores/fs/`](client/stores/fs/DESIGN.md) — Filesystem-backed credential store that persists oneauth client server credentials as a single JSON file keyed by normalized server URL.
11. [`admin/`](admin/DESIGN.md) — OneAuth's client-administration surface — RFC 7591 Dynamic Client Registration, RFC 7592 self-service registration management, the proprietary /apps registry, admin-side CRUD, signing-key rotation with grace periods, and resource-token minting.
12. [`apiauth/`](apiauth/DESIGN.md) — Transport-independent OAuth 2.0 core (issue / validate / introspect / revoke / authenticate clients) plus thin HTTP bindings for the token endpoint, RFC 7662 introspection, RFC 7009 revocation, RFC 8414 AS metadata, RFC 9728 protected-resource metadata, and resource-server middleware.
13. [`keystoretest/`](keystoretest/DESIGN.md) — Shared conformance test suite that every KeyStorage backend (inmem, gorm, fs, gae) runs against to prove uniform behaviour for put/get/delete, kid resolution, and asymmetric key round-trips.
14. [`kidstoretest/`](kidstoretest/DESIGN.md) — Shared conformance test suite that every keys.KidStorage backend runs against its own factory to prove uniform contract compliance.
15. [`stores/gae/`](stores/gae/DESIGN.md) — Google Cloud Datastore-backed implementations of oneauth's key, kid, user, identity, channel, auth-token, refresh-token, API-key, and username store interfaces.
16. [`appstoretest/`](appstoretest/DESIGN.md) — Shared contract test suite that every AppRegistrationStore backend (inmem, fs, gorm) runs against to prove behavioral parity.
17. [`stores/fs/`](stores/fs/DESIGN.md) — Filesystem-backed (JSON file per record) implementations of OneAuth's key, kid, app, user, username, identity, channel, token, refresh-token, and API-key stores for single-process dev and small deployments.
18. [`stores/gorm/`](stores/gorm/DESIGN.md) — GORM/SQL-backed implementations of every oneauth store interface (users, identities, channels, tokens, refresh tokens, API keys, usernames, signing keys, kid keys, app registrations) plus AutoMigrate, usable on any GORM driver.
19. [`testutil/`](testutil/DESIGN.md) — In-process OAuth authorization server plus standalone OAuth/JWT helpers for oneauth integration tests.
