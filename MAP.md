## Suggested reading order

Roots first; folders that depend on others appear after their dependencies. Each folder name links to that folder's DESIGN.md so the reader can dive in directly.

1. [`core/`](core/DESIGN.md) — Foundation data model, store interfaces, token/scope/credential types, and RFC 9396 authorization details that every other OneAuth package imports.
2. [`grpc/`](grpc/DESIGN.md) — Propagates an authenticated user ID across the HTTP-to-gRPC boundary via gRPC metadata, with server-side interceptors that enforce (or optionally relax) authentication per method.
3. [`oauth2/`](oauth2/DESIGN.md) — Embeddable OAuth2 authorization-code-flow providers (Google, GitHub) with PKCE and CSRF-state protection, packaged as a standalone Go module decoupled from oneauth core.
4. [`utils/`](utils/DESIGN.md) — Crypto and encoding helpers for OneAuth — keypair generation, PEM parsing, JWK/JWKS conversion, RFC 7638 thumbprint kid derivation, and Flask session-cookie interop.
5. [`client/`](client/DESIGN.md) — Client-side OAuth 2.0 SDK for oneauth — credential storage, automatic token refresh, AS discovery, browser/headless login (auth-code+PKCE), client_credentials and private_key_jwt flows, and dynamic client registration.
6. [`httpauth/`](httpauth/DESIGN.md) — HTTP-layer authentication for browser flows — session/cookie/JWT user-extraction middleware, OAuth callback + account-linking mux, and standalone CSRF, body-limit, and security-header middlewares.
7. [`keys/`](keys/DESIGN.md) — JWT signing-key management — storage interfaces, in-memory and encrypted backends, kid-indexed grace-period retention for rotation, and JWKS endpoint serving/fetching.
8. [`localauth/`](localauth/DESIGN.md) — Form-based local username/password authentication — signup, login, email verification, password reset, and channel-aware/incremental credential linking — built on top of core store interfaces.
9. [`admin/`](admin/DESIGN.md) — Admin authentication, app/client registration (proprietary + RFC 7591 DCR + RFC 7592 management), and resource-token minting for OneAuth's federated auth flow.
10. [`apiauth/`](apiauth/DESIGN.md) — Transport-independent OAuth 2.0 authorization-server and resource-server core — token issuance, validation, introspection, revocation, and client authentication — plus thin HTTP bindings (token/introspect/revoke endpoints, discovery metadata, and bearer middleware).
11. [`stores/gae/`](stores/gae/DESIGN.md) — Google Cloud Datastore implementations of the oneauth store interfaces (keys, users, identities, channels, tokens, API keys, usernames), with multi-tenancy via Datastore namespaces.
12. [`stores/fs/`](stores/fs/DESIGN.md) — Filesystem-backed (one-JSON-file-per-record) implementations of OneAuth's core store interfaces, intended for single-process dev/test deployments.
13. [`stores/gorm/`](stores/gorm/DESIGN.md) — GORM/SQL-backed implementations of the oneauth store interfaces (users, identities, channels, tokens, API keys, usernames, signing keys, kid grace store, app registrations) usable against any GORM-supported driver.
14. [`testutil/`](testutil/DESIGN.md) — Reusable, t.Fatal-based test infrastructure — an in-process RSA-signing authorization server plus standalone OAuth/JWT helpers — importable by oneauth's own suites and downstream projects.
