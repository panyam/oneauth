## Suggested reading order

Roots first; folders that depend on others appear after their dependencies. Each folder name links to that folder's DESIGN.md.

1. [`accounts/`](accounts/DESIGN.md) — Owns the federated end-user account model (User, Identity, Channel) and store interfaces shared by local and provider-mediated auth flows — explicitly excludes HTTP handlers and OAuth token shapes.
2. [`core/`](core/DESIGN.md) — Transport-level foundation types — tokens, scopes, RFC 9396 authorization details, blacklist / rate-limit primitives, and a typed subject context shim — shared across every OneAuth subpackage.
3. [`grpc/`](grpc/DESIGN.md) — Authentication context utilities and server interceptors that propagate the authenticated subject (RFC 7519 `sub`) across the HTTP-to-gRPC boundary via metadata, with optional per-method auth enforcement and a dev-only switch-user impersonation header.
4. [`httpauth/`](httpauth/DESIGN.md) — HTTP-layer plumbing for session-based auth — a session/JWT-aware login mux, a pluggable subject-resolution middleware, and standalone CSRF / body-limit / security-header middlewares.
5. [`oauth2/`](oauth2/DESIGN.md) — Self-contained OAuth2 social-login providers (Google, GitHub) with a shared base, PKCE (RFC 7636), and state-cookie CSRF protection that deliver the authenticated user to a host-supplied callback.
6. [`saml/`](saml/DESIGN.md) — POC SAML 2.0 Service Provider adapter that mounts SP-initiated SSO/SLO routes on a gorilla/mux router and bridges the SAML assertion into oneauth's OAuth-shaped HandleUserFunc callback.
7. [`utils/`](utils/DESIGN.md) — Stateless crypto and encoding helpers — RSA/ECDSA key generation, PEM/PKCS8 codec, JWK/JWKS conversion, RFC 7638 kid thumbprints, JWT signing-method lookup, and Flask session-cookie decoding.
8. [`localauth/`](localauth/DESIGN.md) — Local username/password authentication — HTTP handlers and store-backed callbacks for signup, login, email verification, password reset, and credential linking onto OAuth-only users.
9. [`federatedauth/`](federatedauth/DESIGN.md) — Orchestrates provider-mediated (OAuth/SAML) authentication callbacks — turning provider userInfo into an accounts.User, linking new channels onto existing users, and establishing the session via httpauth.
10. [`client/`](client/DESIGN.md) — Client-side OAuth SDK — discovers authorization servers, drives browser/CLI/M2M login flows, caches and refreshes tokens, and injects them into HTTP requests.
11. [`keys/`](keys/DESIGN.md) — Signing-key storage, kid-indexed lookup, encryption-at-rest, grace-period rotation, and JWKS publication/consumption for OneAuth.
12. [`client/stores/fs/`](client/stores/fs/DESIGN.md) — Filesystem-backed CredentialStore that persists per-server ServerCredential entries in a single JSON file with owner-only permissions.
13. [`admin/`](admin/DESIGN.md) — OneAuth's client-administration surface — RFC 7591 Dynamic Client Registration, RFC 7592 self-service registration management, the proprietary /apps registry, admin-side CRUD, signing-key rotation with grace periods, and resource-token minting.
14. [`apiauth/`](apiauth/DESIGN.md) — API token authentication — token issuance (password / refresh / client_credentials / jwt-bearer / token-exchange), JWT validation middleware, RFC 7662 introspection, RFC 7009 revocation, RFC 8414 / OIDC discovery, and a transport-independent `OneAuth` core that composes focused interfaces (`TokenIssuer` / `TokenValidator` / `TokenIntrospector` / `TokenRevoker` / `ClientAuthenticator`).
15. [`keystoretest/`](keystoretest/DESIGN.md) — Shared conformance test suite that every `keys.KeyStorage` backend (inmem, fs, gorm, gae) runs against to prove uniform put/get/delete/list, kid resolution, and asymmetric key round-trip semantics.
16. [`kidstoretest/`](kidstoretest/DESIGN.md) — Shared conformance test suite that every `keys.KidStorage` backend (in-memory KidStore, FS, GORM, GAE) drives via a per-test factory to prove uniform contract compliance.
17. [`stores/gae/`](stores/gae/DESIGN.md) — Google Cloud Datastore-backed implementations of oneauth's account/identity/channel/token/key/username stores, with namespacing, JSON-blob payloads, and transactional rotation/revocation flows.
18. [`appstoretest/`](appstoretest/DESIGN.md) — Shared contract test suite that every `admin.AppRegistrationStore` backend (InMem, FS, GORM) runs against to prove behavioral parity.
19. [`stores/fs/`](stores/fs/DESIGN.md) — File-backed implementations of every oneauth store interface, optimized for dev and single-node deployments via file-per-record JSON layouts with atomic temp-file + rename writes.
20. [`testutil/`](testutil/DESIGN.md) — Shared test setup helpers for oneauth — an in-process RS256 OAuth AS plus OIDC discovery, token-grant, JWKS, and JWT introspection fixtures used across package test suites.
21. [`stores/gorm/`](stores/gorm/DESIGN.md) — GORM/SQL-backed implementations of every oneauth store interface (users, identities, channels, verification tokens, refresh tokens, API keys, usernames, signing keys, kid keys, app registrations), all on the `(ctx, *XRequest) → (*XResponse, error)` gRPC-shape contract, with a single AutoMigrate and portability across SQLite/MySQL/Postgres.
